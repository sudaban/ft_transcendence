# ft_transcendence Authentication & 2FA API Guide

A complete reference for frontend developers integrating the registration, login, and Two-Factor Authentication (2FA) flows. 

---

## 🔐 The 2FA Handshake Architecture

This system implements Time-Based One-Time Passwords (TOTP - RFC 6238). To keep user accounts secure and prevent bypass exploits, the authentication flow is split into a multi-step handshake:

### 1. Interactive Login Flow
1. **First Factor**: The user submits their email and password to `/api/auth/login`.
2. **If 2FA is Disabled**: The server immediately returns `requiresTwoFactor: false` and the final JWT `token`. You are done; log the user in.
3. **If 2FA is Enabled**: The server returns `requiresTwoFactor: true` and a short-lived `tempToken` (valid for 5 minutes). The final JWT is `null`.
4. **Second Factor**: You catch `requiresTwoFactor: true`, preserve the `tempToken` and the user's `email` in your application state, and render the 6-digit OTP code prompt.
5. The user enters their code. You submit a POST to `/api/auth/2fa/login` containing the `email`, the 6-digit `code`, and the `tempToken`.
6. If verified, the server yields the final JWT `token`. Replace the temp state and grant access.

### 2. Device Setup & Activation Flow
1. The user logs in and navigates to their profile/security settings.
2. They click "Enable 2FA", triggering a POST to `/api/auth/2fa/setup` (carrying their Bearer JWT).
3. The server generates a unique Base32 key and returns a standard `qrCodeUri` along with the raw `secretKey` (as a fallback).
4. Render the `qrCodeUri` as a QR code. The user scans it with their authenticator app (Google Authenticator, Microsoft Authenticator, 2FAS, etc.).
5. The user types the first 6-digit code shown in their app. Send it via POST to `/api/auth/2fa/enable`.
6. If correct, the server binds the secret and flips `IsTwoFactorEnabled` to true.

## 🚀 API Endpoint Reference

All payloads and responses use `application/json`.

### 1. User Registration (Register)
Creates a new account and signs the user in immediately.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/register`
* **Authorization**: None (Public)

**Request Body**:
```json
{
  "username": "coder123",
  "email": "dev@example.com",
  "password": "SuperSecurePassword99!"
}
```

**Response (200 OK)**:
```json
{
  "message": "Registration successful",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

---

### 2. User Authentication (Login)
Validates email/password credentials and checks 2FA requirements.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/login`
* **Authorization**: None (Public)

**Request Body**:
```json
{
  "email": "dev@example.com",
  "password": "SuperSecurePassword99!"
}
```

**Response - Scenario A (2FA Disabled)**:
```json
{
  "requiresTwoFactor": false,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tempToken": null
}
```

**Response - Scenario B (2FA Enabled)**:
```json
{
  "requiresTwoFactor": true,
  "token": null,
  "tempToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

---

### 2b. OAuth 2.0 Remote Login (OAuth Login)
Authenticates or registers a user via an external OAuth provider (42 or Google).

* **HTTP Method**: `POST`
* **Path**: `/api/auth/oauth/login`
* **Authorization**: None (Public)

**Request Body**:
```json
{
  "provider": "42",
  "code": "AUTH_CODE_FROM_PROVIDER",
  "redirectUri": "https://localhost/auth/callback"
}
```

**Response - Scenario A (2FA Disabled / Registered successfully)**:
```json
{
  "requiresTwoFactor": false,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tempToken": null
}
```

**Response - Scenario B (2FA Enabled)**:
```json
{
  "requiresTwoFactor": true,
  "token": null,
  "tempToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

---

### 3. Second-Factor Verification (2FA Login)
Validates the TOTP code against the temporary token generated during step 1.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/2fa/login`
* **Authorization**: None (Public - passes `tempToken` in body)

**Request Body**:
```json
{
  "email": "dev@example.com",
  "code": "589412",
  "tempToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**Response (200 OK)**:
```json
{
  "requiresTwoFactor": false,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tempToken": null
}
```

---

### 4. Initialize 2FA Setup
Generates a new TOTP secret key for an authenticated user.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/2fa/setup`
* **Authorization**: `Bearer <Token>` (Active session JWT required)

**Response (200 OK)**:
```json
{
  "secretKey": "ORSXG5BRGIZTINJWG44DS",
  "qrCodeUri": "otpauth://totp/ft_transcendence:dev%40example.com?secret=ORSXG5BRGIZTINJWG44DS&issuer=ft_transcendence&algorithm=SHA1&digits=6&period=30"
}
```

---

### 5. Finalize 2FA Activation (Enable)
Verifies the first code generated by the user's authenticator app to officially activate 2FA protection.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/2fa/enable`
* **Authorization**: `Bearer <Token>` (Active session JWT required)

**Request Body**:
```json
{
  "code": "123456"
}
```

**Response (200 OK)**:
```json
{
  "message": "Two-factor authentication enabled successfully."
}
```

---

### 6. Deactivate 2FA (Disable)
Disables 2FA and purges the stored secret key from the user's account.

* **HTTP Method**: `POST`
* **Path**: `/api/auth/2fa/disable`
* **Authorization**: `Bearer <Token>` (Active session JWT required)

**Response (200 OK)**:
```json
{
  "message": "Two-factor authentication disabled successfully."
}
```

## 🗺️ Frontend Integration Blueprint

Here is a recommended implementation guide to help you build a robust and user-friendly frontend client:

### Step 1: Manage Auth State Transitions
- In your central store (Pinia, Redux, Context, etc.), track three auth states: `IsAuthenticated`, `Is2faPending`, and `ActiveUser`.
- If the login response yields `requiresTwoFactor: true`, set `Is2faPending = true`, save the `tempToken` and the `email` to state, and redirect the user to a secure `/login/2fa` route.
- Block the user from accessing `/login/2fa` directly if `tempToken` is missing.

### Step 2: Build a Smooth OTP Input Component
- Create an input component with six separate single-digit character fields.
- Listen to keyboard events:
  - On character input, automatically focus the next input field.
  - On backspace, focus the previous input field.
  - Listen for paste events so users can copy-paste a full 6-digit code.
- Implement a 5-minute countdown timer on the UI based on the `tempToken` lifespan. If it expires, clear the state, redirect back to `/login`, and show a "Your verification session has expired. Please log in again" notification.

### Step 3: Implement Setup & QR Code Rendering
- Under the user's Security Settings page, display a toggle or button to enable 2FA.
- When clicked, call `/api/auth/2fa/setup` and pass the response `qrCodeUri` into a client-side QR renderer component (e.g. `qrcode.vue`, `react-qr-code`, or a library-free canvas generator).
- Display the raw `secretKey` (e.g., `ORSXG5BRGIZTINJWG44DS`) in a "copyable" layout as a fallback for users who cannot scan QR codes.
- Do not mark 2FA as active until the user enters their first valid verification code and `/api/auth/2fa/enable` returns a successful response.

### Step 4: Handle API Exceptions Gracefully
- Check API HTTP response codes:
  - `400 Bad Request` or `401 Unauthorized` means the OTP code is invalid or the session has expired. Show a precise inline warning to the user.
  - Clear the input boxes and focus the first field automatically on failure.
